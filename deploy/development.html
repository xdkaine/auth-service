The application has its own namespace, copied runtime Secret/CA/ConfigMap, and default-deny policies. Explicit rules permit DNS, existing directory/HTTPS destinations and the shared development database/Redis. Portal can reach Auth across namespaces. Production Auth remains in auth.

The root-run cutover script prepares resources, switches the development proxy and delivery target, then retires the old deployment after validation. Stop the application-delivery timer and service during the cutover, run the verification helper, save the private steady-state snapshot, and restart delivery after the new target is verified. The restore phase can reconstruct namespace resources from that snapshot using the current delivery image; use current credential backups if keys have since rotated. It is an operator migration, not a CI step. Secret-bearing snapshots remain in the server's private cutover directory. Do not rerun completed cutover phases without checking current state. No database migration or volume deletion is involved.

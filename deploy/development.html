The application has its own namespace, copied runtime Secret/CA/ConfigMap, and default-deny policies. Explicit rules permit DNS, existing directory/HTTPS destinations and the shared development database/Redis. Portal can reach Auth across namespaces. Production Auth remains in auth.

The root-run cutover script prepares resources, switches the development proxy and delivery target, then retires the old deployment after validation. Stop the application-delivery timer and service during the cutover, run verify-auth-dev.py, save the private steady-state snapshot, and restart delivery after the new target is verified. The snapshot is cutover-time rollback evidence, not a current credential backup. There is no automatic restore phase. It is an operator migration, not a CI step. Secret-bearing snapshots remain in the server's private cutover directory. Do not rerun completed cutover phases without checking current state. No database migration or volume deletion is involved.

Reconstructing the namespace

Declarative resource template contains no Secrets or allocated Service IP. Replace documentation-only 192.0.2.57/32 and 192.0.2.20/32 with the reviewed proxy/directory CIDRs, and set the Deployment image from the current deploy/dev receipt. Preserve the existing development LDAP certificate exception only where explicitly approved.

  1. Restore the backing PostgreSQL/Redis services and data first.
  2. Create the Namespace with its Pod Security labels. Provision current uar-auth-runtime and uar-database-ca Secrets from authoritative backups; never reuse stale signing keys after a deliberate rotation.
  3. Apply the ConfigMap, all network policies (including the Portal repository's cross-namespace policies), and Service before the Deployment.
  4. Wait for readiness, verify dependencies and issuer/keys, then set the development Nginx upstream to the actual allocated Service IP and reload only after nginx -t passes.
  5. Confirm the Portal compatibility alias and server delivery target use auth-dev. Verify public discovery, Portal access and session behavior before resuming delivery.

During the initial move, the compatibility Service may temporarily carry kustomize.toolkit.fluxcd.io/reconcile=disabled until the Portal deployment branch contains the matching ExternalName manifest. Remove that temporary annotation once the release catches up.
